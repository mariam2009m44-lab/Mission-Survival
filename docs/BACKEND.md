# Backend deployment (Cloudflare Workers + D1)

The game remains playable without an API. Until `src/backend-config.js` contains the deployed HTTPS Worker URL, progress is saved locally only. When connected, the app sends a minimal, validated progress snapshot to the API.

## What the backend stores

- Random guest commander ID (generated by the server), selected avatar and interface language.
- Training completion, aggregate XP / mission totals, and a compact mission progress record.
- No email, password, full name, birth date, precise location, chat messages, or public leaderboard.
- Guest sessions are device-specific. This is not cross-device account recovery or a parental account system.

## Deploy

Requirements: a Cloudflare account and Node.js 22+.

1. Install Wrangler temporarily and authenticate:
   ```bash
   npx wrangler@latest login
   ```
2. Create the D1 database:
   ```bash
   npx wrangler@latest d1 create lunar-outpost --config backend/wrangler.toml
   ```
3. Copy the returned database ID into `backend/wrangler.toml`, replacing `REPLACE_WITH_YOUR_CLOUDFLARE_D1_DATABASE_ID`.
4. Apply the schema:
   ```bash
   npx wrangler@latest d1 migrations apply lunar-outpost --remote --config backend/wrangler.toml
   ```
5. Set a private signing secret (never commit it):
   ```bash
   openssl rand -base64 48
   npx wrangler@latest secret put SESSION_SECRET --config backend/wrangler.toml
   ```
   Paste the generated value when Wrangler asks. Use a different secret for production and keep it private.
6. Deploy:
   ```bash
   npx wrangler@latest deploy --config backend/wrangler.toml
   ```
7. Copy the HTTPS `workers.dev` URL into `API_BASE_URL` in `src/backend-config.js`, commit that one-line configuration change, and let GitHub Pages deploy.
8. Check `https://YOUR-WORKER-URL/health`. It should return `{"ok":true,"service":"lunar-outpost-api","version":1}`.

The Worker allows the project GitHub Pages origin plus local development origins. If the Pages owner/repository URL changes, update `ALLOWED_ORIGINS` in `backend/wrangler.toml` before deploying.

## API

- `GET /health` — health check.
- `POST /v1/session` — creates an anonymous guest session and signed 30-day token.
- `GET /v1/state` — reads the current guest's saved progress.
- `PUT /v1/state` — validates and saves a compact progress snapshot.

All state routes require a Bearer token. The server allowlists fields, clamps numeric values, limits mission history to five decisions, and does not accept arbitrary profile fields. The client always keeps a local copy so a network failure does not block gameplay.

## Important production boundary

This is a first backend foundation, not a full account platform. Guest tokens live on the same device; losing browser storage means losing access to that guest cloud record. Cross-device login, parental controls, administrator dashboards, and leaderboard features are intentionally not enabled. Before adding accounts for children, design a privacy and parental-consent flow and review applicable laws and platform policies.
